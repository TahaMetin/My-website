Bankacılık mikroservisleri için Java 21 geçişi

Canlıdaki birden çok mikroservisin Java 8 ve 17'den Java 21'e yükseltilmesi: javax → jakarta geçişi, Spring Boot yükseltmeleri ve Maven/Gradle bağımlılık güncellemeleri.

Rol
Yazılım Mühendisi, katkıda bulunan
Teknolojiler
Java 8 / 17 → 21, Jakarta EE, Spring Boot, Maven, Gradle
Teslimat
Azure DevOps (TFS), Digital.ai Release
BağlamRolümYaptıklarımSonuç

Bağlam

Birçok bankacılık ürününün arkasındaki servisler Java 8 ve Java 17 karışımı üzerinde çalışıyordu. Eski çalışma ortamları; eski framework sürümleri, yaşlanan bağımlılıklar ve ekipler arasında ayrışan derleme yapıları demekti. Platform ekibi, servisleri Java 21'e taşımak için altyapı çalışması başlattı.

Java 8 / 17 servisleri→Java 21, Spring Boot yükseltmesi→javax → jakarta→Bağımlılıklar, derleme hataları, testler→Azure DevOps → Digital.ai Release

Rolüm

Geçiş altyapısı çalışmasına katkı verdim ve derleme dosyalarından başarılı bir pipeline çalışmasına kadar birden çok mikroservisi kendim yükselttim.

Yaptıklarım

  • Her servisin Java sürümünü 21'e çıkardım ve Spring Boot'u uyumlu bir sürüme yükselttim.
  • Yeni Spring Boot neslinin gerektirdiği javax → jakarta paket adı geçişini yaptım.
  • Maven ve Gradle bağımlılıklarını güncelledim; yeni çalışma ortamını desteklemeyen kütüphaneleri değiştirdim ya da sürümlerini yükselttim.
  • Yükseltmenin ortaya çıkardığı derleme hatalarını ve başarısız testleri, servislerin davranışını değiştirmeden düzelttim.
  • Her servisi Azure DevOps'taki CI/CD pipeline'ından geçirip Digital.ai Release ile sürüme taşıdım.

Sonuç

Taşınan servisler güncel framework ve bağımlılık sürümleriyle, uzun süreli destekli (LTS) güncel bir Java sürümünde çalışıyor. Bu da sonraki yükseltmeleri ve güvenlik yamalarını kolaylaştırıyor.

Ayrıntılar müşteri gizliliği gereği genelleştirildi. Müşteri verisi gösterilmiyor.
