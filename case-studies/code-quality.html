Code quality and test coverage

Writing unit tests to raise coverage and resolving SonarQube findings, using in-house AI-assisted tooling to speed up coding, test writing and debugging.

Role
Software Engineer
Stack
Java, unit testing, SonarQube
Tooling
OpenCode with DeepSeek and GLM models

Context

Banking services live for a long time and change often. Low test coverage and open static-analysis findings make every change riskier and slow down reviews.

My role

Alongside feature work, I took on improving the test coverage and SonarQube results of the services I worked on.

What I did

  • Wrote unit tests for untested code paths to raise coverage.
  • Resolved SonarQube findings to improve maintainability.
  • Used OpenCode, integrated with DeepSeek and GLM models, to draft tests, explore unfamiliar code and debug faster, reviewing every suggestion before it went in.

Outcome

Higher test coverage and fewer open SonarQube findings on the services I touched, giving the team more confidence when shipping changes.

Details are generalised to respect client confidentiality.
