Integration flows to the decision engine

webMethods flow services that take data from newly built services and route it to Java backend services, either to be stored in Oracle or processed by the decision engine.

Role
Software Engineer
Stack
webMethods (Software AG), Java, Spring Boot, Oracle
Interfaces
REST, SOAP

Context

New services were being introduced for banking products, and their data had to reach existing Java backends. Some of it needed to be persisted; some of it fed the decision engine. webMethods sits between the two as the integration layer.

New service→ webMethods flow service→ Java / Spring Boot backend→ Oracle DBor Decision engine

My role

I built the webMethods flow services and worked on the Java services on the receiving end, so I owned the path from consuming the data to handing it over to persistence or decisioning.

What I did

  • Built flow services that consume data from the new services and map it to what the backends expect.
  • Routed each message to the right Java backend service over REST or SOAP.
  • Developed and maintained the Spring Boot microservices that persist the data in Oracle or pass it to the decision engine.
  • Investigated and fixed defects along the flow and resolved related incident records.

Outcome

New services could feed the existing backends and the decision engine through a single integration layer, without each one wiring itself directly to every backend.

Details are generalised to respect client confidentiality.
